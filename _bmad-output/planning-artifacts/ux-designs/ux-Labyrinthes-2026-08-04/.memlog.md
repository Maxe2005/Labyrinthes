- (change) Navigation revised: Home is the ONLY router between Builder and Player — no direct top-bar Builder/Player switch (supersedes the switcher shown in the direction-blueprint.html mockups); top bar instead carries a 'Home' / breadcrumb-back affordance
- (decision) Error/empty states: inline contextual messages next to the concerned field/action (e.g. invalid dimensions under the input), not modal dialogs — consistent with Blueprint's precise/technical register
- (decision) Accessibility floor: full keyboard operability (every action has a shortcut), visible focus indicator, WCAG AA text/background contrast, entry/exit/wall distinguished by shape+color not color alone. Screen-reader support explicitly out of scope, documented as a known Tkinter platform limitation rather than an unmet goal
- (decision) Navigation exception: a contextual 'Test in Player' action in the Builder opens the Player directly on the current maze, bypassing Home — deliberate exception to the Home-only-router rule for this frequent work loop; same bidirectional idea should exist as 'Edit in Builder' from a maze context in Player where relevant
- (change) UJ-C revised: activating HARD (or any Level/Difficulty) for the first time triggers an explanatory popup describing how that mode works; same popup exists for every Level/Difficulty tier, first-activation-triggered. Auto-show-on-first-activation is configurable in Settings (can be turned off). Independent of that setting, the popup must stay easily reachable on demand via a visible info/help affordance next to the Level/Difficulty control while the player is experimenting with it
- (decision) Key flows locked: UJ-A (Priya discovers the game, first launch through a classic maze win), UJ-B (Max builds and tests a maze via the Test-in-Player exception), UJ-C (Priya tries HARD mode, first-activation explainer popup, timeout failure with inline message)
- (change) Broken wall state revised: a broken wall is NOT drawn with a dashed/pattern bar — it is simply absent (a clean gap in the grid), so the player unambiguously sees the wall is gone rather than confusing a pattern for a wall variant
- (change) Shortcut display revised: keyboard shortcuts are NOT printed persistently on buttons (supersedes the always-visible kbd tags shown in the direction-blueprint.html mockup, which was part of that direction's 'medium-high density, shortcuts always on display' rationale) — instead each button carries an attached label/tooltip that reveals the shortcut only on hover
- (change) Shortcut display corrected (supersedes the immediately prior hover-only change): keyboard shortcuts DO stay printed on the button itself (back to the kbd-tag-on-button pattern from direction-blueprint.html). ADDITIONALLY, each button carries an attached tooltip, visible only on hover, that describes what the action DOES (a plain-language description of the button's effect, not a restatement of the shortcut)
- (decision) AA contrast fix: add colors.accent-on-tint (#1d4ed8) as the TEXT color used only when accent text sits on the accent-bg tint (light-mode tool-btn active state, was ~4.2:1) — restores AA. Add colors.accent-strong-dark (#1e40af) as the BACKGROUND FILL used only for primary-emphasis controls in dark mode (e.g. primary pill-btn), replacing accent-dark there, because white text on accent-dark alone measured ~3.3:1 — accent-dark remains the lighter general interactive/live accent everywhere else (ball, live HUD chip)
