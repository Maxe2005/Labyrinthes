- (decision) Paradigm: Hexagonal / Ports & Adapters — maze engine (grid, cells, generation, resolution, game rules) has zero dependency on Tkinter or storage; Tkinter and persistence are adapters implementing ports. Chosen over layered because the legacy 'big_boss' anti-pattern shows convention-only separation leaks over time; a structural boundary is preferred (Max's choice).
- (decision) OQ1 resolved: web-adapter horizon is near, not distant — Max plans to start a web implementation shortly after legacy feature parity lands in the new implementation, possibly sooner. Implication: design the rendering/interaction ports with real care now (not a throwaway single-adapter shortcut), since a second adapter is coming soon.
- (decision) OQ4 resolved: legacy data migration via a one-time conversion script (run once, converts Labyrinthes_classiques/ etc. and the entité,nom,valeur settings CSV to the new English layout/format, then retired) — no permanent dual-format read compatibility layer in the storage adapter (Max's choice).
- (decision) State management: immutable domain — Grid/Cell/Maze are immutable value objects; engine operations (break wall, generate, solve) are pure functions taking a state and returning a new state. Adapters (Tkinter now, web later) own the mutable 'current state' pointer and re-render after each engine call. Chosen for testability and convergence between present and future adapters on the same re-render-after-change pattern (Max's choice).
- (decision) Settings persistence (fixes FR-21, respects FR-4's 'defined once, read by both'): three scopes — builder-private, game-private, shared (e.g. size bounds). SettingsRepository port exposes only scoped get(scope,key)/set(scope,key,value), written immediately to disk — never a legacy-style load-everything-in-memory/dump-everything-on-close, which was the actual root cause of the concurrent-overwrite bug (a stale in-memory copy of the OTHER app's section getting redumped). Refined after Max flagged that a naive per-app file split alone would break FR-4's single-source-of-truth requirement for shared settings (Max's insight).
- (decision) Module boundaries confirmed: src/labyrinthes/{domain,application,adapters/{tkinter,storage},app}/ — domain/application pure and framework-free; adapters implement ports; app/ holds the two composition roots (builder, player). No shared generic Renderer port between Tkinter and a future web adapter — each UI adapter owns its own rendering, calling into application services; only persistence (MazeRepository, SettingsRepository) is a real port (Max's choice).
- (decision) Domain/UI boundary enforcement: a pytest test scans domain/ and application/ source for forbidden imports (tkinter, adapters) and fails the suite if found — no new dependency, runs alongside the existing ruff+pytest quality gate (Max's choice).
